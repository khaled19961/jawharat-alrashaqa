# حالة نقل واجهة D-Nutrition-Care إلى Odoo

## ما تم التحقق منه

- المستودع المصدر هو `khaled19961/-D-Nutrition-Care`، وهو تطبيق Next.js 16 / React 19 يستخدم Tailwind CSS وCloudflare Workers وSupabase.
- الصفحة الرئيسية تُحمّل البنرات والمنتجات والتصنيفات من Supabase، وتحتوي على صفحتين ثابتتين للبنرات ثم مسار بنرات متحركة، وبطاقات تصنيفات ومنتجات وأقسام ترويجية.
- يوجد في مستودع المصدر ثلاثة ملفات بنرات محلية فقط: `public/banners/moving-01.png` و`moving-02.png` و`moving-03.png`.
- صور البنرات النشطة الأخرى في الصفحة الرئيسية تُقرأ من جدول `site_banners`؛ لم يتم الاتصال بقاعدة البيانات أو تصديرها أو تعديلها في هذه المرحلة.

## ما أُنشئ في هذا الفرع

- وحدة أولية `addons/jawharat_storefront` تعتمد على `website` و`website_sale`.
- قالب رأس وتذييل بهوية عربية RTL، وقالب الصفحة الرئيسية يقرأ المنتجات والتصنيفات المنشورة من Odoo.
- نموذج لإدارة البنرات من واجهة Odoo، مع موضع ثابت/متحرك، وترتيب، ورابط، ونص بديل.
- نسخة من ملف CSS الأصلي بعد إزالة توجيه Tailwind الخاص بالبناء، مع طبقة تكييف بسيطة لقوالب Odoo.

## قيود يجب حلها قبل اعتبار النقل مكتملًا

1. لم تُختبر الوحدة على خادم Odoo 20 فعلي، ولم تُثبّت على أي قاعدة بيانات.
2. لم تُنقل صور البنرات الثابتة أو جميع صور البنرات المتحركة من Supabase؛ يوجد fallback مؤقت لثلاث صور من موقع المصدر. يجب تصدير الصور المطلوبة بصورة مستقلة ثم رفعها إلى سجل البنرات في Odoo أو تضمينها كأصول محلية.
3. لم تُنقل سجلات المنتجات والعملاء والطلبات ولا إعدادات الدفع أو الشحن ولا بيانات Supabase.
4. CSS الأصلي يشمل تنسيقات صفحات متعددة؛ يلزم فحص بصري وتخفيف أي قواعد لا تخص المتجر بعد تجربة القالب.
5. يجب التحقق من أسماء الحقول ومعرّفات قوالب Odoo 20 ونجاح XML/QWeb على بيئة اختبار قبل التثبيت.

## إجراءات الأمان

- لا يوجد نشر إلى Odoo أو Cloudflare من هذا الفرع.
- لا توجد عمليات كتابة إلى Supabase أو قاعدة بيانات أخرى.
- لا تُضف مفاتيح API أو بيانات دخول أو بيانات عملاء إلى المستودع.
