# مساعد جوهرة الرشاقة السحابي — Cloudflare Workers AI

هذا مشروع مستقل لتشغيل واجهة محادثة عربية على Cloudflare، وربطها بنقطة Odoo MCP لمتجر جوهرة الرشاقة. يستخدم النموذج المستضاف `@cf/zai-org/glm-4.7-flash` عبر Cloudflare Workers AI، لذلك لا يحتاج إلى تشغيل النموذج على كمبيوتر المستخدم.

## الحالة الحالية

- ملفات المشروع أُضيفت إلى فرع `odoo-port` في GitHub.
- لم يتم نشر Worker ولم يتم الاتصال بقاعدة Odoo فعليًا بعد.
- يلزم إعداد الأسرار في Cloudflare، ثم اختبار اتصال MCP والتحقق من أدوات Odoo المتاحة.
- هذا المشروع مساعد خاص، وليس جزءًا من واجهة المتجر العامة، ولا يغيّر المتجر تلقائيًا عند مجرد نشره.
- الواجهة تستخدم كلمة مرور خاصة، والاتصال بـ Odoo مخزّن في أسرار الخادم. لا تُحفظ مفاتيح Odoo في GitHub أو ملفات المتصفح.

## المسار

`tools/jawharat-odoo-assistant/`

## المتطلبات

- حساب Cloudflare يمكنه إنشاء Workers واستخدام Workers AI ضمن الخطة المجانية.
- حساب Odoo Online لمتجر `https://jawharat-alrashaqa.odoo.com`، مع إمكانية إنشاء API key بنطاق MCP.
- رصيد Workers AI المجاني المتاح. حد الاستخدام المجاني المنشور هو 10,000 Neurons يوميًا؛ قد تتوقف الطلبات عند بلوغ الحد على حساب Workers Free. لا تفعّل خطة مدفوعة بغرض تجاوز الحد دون مراجعة التكلفة.

## النشر من GitHub دون تشغيل البناء على جهازك

1. افتح Cloudflare Dashboard ثم Workers & Pages وأنشئ Worker جديدًا عبر استيراد مستودع Git.
2. اختر المستودع `khaled19961/jawharat-alrashaqa` والفرع `odoo-port`.
3. اضبط Root directory على `tools/jawharat-odoo-assistant`.
4. اجعل Build command هو `npm run build` وDeploy command هو `npx wrangler deploy`. استخدم إصدار Node.js الذي يوصي به Cloudflare لبناء مشروع Vite الحالي.
5. راجع إعدادات Worker بعد الربط وتأكد من ظهور AI binding باسم `AI` ومكوّن Durable Object باسم `JawharatOdooAgent` كما هو محدد في `wrangler.jsonc`.

قد تختلف أسماء حقول إعداد البناء قليلًا بحسب واجهة Cloudflare الحالية.

## إعداد اتصال Odoo

### 1. إنشاء مفتاح MCP داخل Odoo

في Odoo افتح قائمة المستخدم ثم My Preferences / تفضيلاتي، وبعدها Security / الأمان، ثم أنشئ API Key بنطاق MCP (وليس صلاحية أوسع من المطلوب). اختر مدة انتهاء قصيرة مثل شهر واحد في البداية. احفظ المفتاح في مكان آمن؛ عادة لا يُعرض مجددًا بعد إغلاق نافذة الإنشاء.

### 2. إضافة متغيرات وأسرار Worker

من إعدادات Worker أضف:

| الاسم | النوع | القيمة |
|---|---|---|
| `ODOO_MCP_URL` | Variable | `https://jawharat-alrashaqa.odoo.com/mcp` |
| `ODOO_MCP_TOKEN` | Secret | مفتاح MCP الذي أنشأته في Odoo |
| `APP_PASSWORD` | Secret | كلمة مرور جديدة وفريدة للدخول إلى واجهة المساعد |
| `SESSION_SECRET` | Secret | قيمة عشوائية طويلة وفريدة لتوقيع الجلسات |

لا ترسل هذه القيم في المحادثة، ولا تضعها في أي ملف داخل GitHub، ولا تستخدم كلمة مرور حساب Odoo ككلمة مرور واجهة المساعد. من الأفضل إنشاء كلمة مرور قوية من مدير كلمات المرور، وإنشاء سر جلسة عشوائي منفصل بطول 32 بايت أو أكثر.

تستمر جلسة الواجهة حتى 8 ساعات ثم تتطلب تسجيل الدخول مجددًا. كلمة المرور ومفتاح Odoo لا يُرسلان إلى نموذج اللغة؛ مفتاح Odoo يستخدمه Worker في الاتصال بالخادم.

## إعداد أدوات MCP في Odoo

- افتح وضع المطور إذا لزم، ثم Settings → Technical → Server Actions.
- راجع الأدوات المتاحة في MCP. ابدأ بأدوات البحث والقراءة فقط.
- إذا احتجت لاحقًا إلى التعديل على الموقع، أتح الأدوات الضرورية للموقع فقط عبر Available in MCP.
- لا تُعرّض أدوات تنفيذ كود عامة أو أدوات تعديل المحاسبة والمخزون والمشتريات ونقاط البيع لهذا المساعد. الكود يستبعد أدوات يَظهر من اسمها أنها تتعلق بهذه المجالات، ويطلب موافقة عبر واجهة المحادثة للأدوات غير المصنّفة قراءة فقط. لا تعتمد على ذلك بدل ضبط الصلاحيات في Odoo.

## اختبار التشغيل الأول

بعد نجاح البناء والنشر:

1. افتح عنوان Worker.
2. سجّل الدخول باستخدام `APP_PASSWORD`.
3. اضغط «فحص الاتصال».
4. ابدأ بطلب قراءة فقط: «اعرض أدوات Odoo المتاحة، وحدد أيها يمكن استخدامه لفحص واجهة الموقع دون تعديل أي سجل».
5. تحقق من أن اتصال Odoo يظهر كـ ready قبل طلب أي تعديل.

لا توافق على أي إجراء إذا كانت مدخلاته تشير إلى الفواتير أو الحسابات أو الزكاة أو الضرائب أو المخزون أو المشتريات أو نقاط البيع أو الأسعار أو الطلبات. يجب أن تظل هذه المجالات خارج نطاق مساعد التصميم.

## تنبيهات مهمة

- هذا المشروع لم يُبنَ أو يُنشر من خلال Cloudflare في هذه المحادثة؛ يلزم تشغيل بناء Cloudflare والتحقق من السجلات قبل الاعتماد عليه.
- Odoo Online يجب أن يتيح نقطة `/mcp` ومفتاح MCP للحساب. إذا لم يكن ذلك متاحًا في خطتك أو بيئتك، فسيفشل الاتصال ويلزم اختيار بديل.
- أدوات تعديل الموقع التي يستطيع الوكيل استعمالها تعتمد على Server Actions التي تكشفها أنت في Odoo. لن يستطيع الوكيل تنفيذ تغيير لا توجد له أداة مسموح بها.
- هذا المشروع لا يحاول تشغيل Next.js الخاص بالواجهة المرجعية داخل Odoo. ملفات `reference/ui-source` تبقى مرجعًا لتصميم المتجر؛ هذا المشروع أداة مساعدة مستقلة.
- لا يُفترض أن الرصيد المجاني غير محدود. يضع Cloudflare حدًا يوميًا للاستخدام المجاني، وقد يلزم الانتظار حتى إعادة تعيين الحد بدل الترقية إلى خطة مدفوعة.
